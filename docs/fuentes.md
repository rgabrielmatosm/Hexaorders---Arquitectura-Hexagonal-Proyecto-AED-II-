# Fuentes primarias y alcance de las afirmaciones

Consulta: **19 de octubre de 2026**. Los ejemplos empresariales conservan la fecha de su publicación: una publicación histórica acredita el caso descrito, sin garantizar el estado interno de toda la empresa en 2026.

| Fuente | Qué respalda | Límite de la afirmación |
| --- | --- | --- |
| [Alistair Cockburn: artículo original de arquitectura hexagonal, 2005](https://alistair.cockburn.us/hexagonal-architecture) | Aislamiento de la aplicación, puertos y adaptadores, pruebas independientes de UI y persistencia. | El hexágono no obliga a seis componentes ni implica microservicios. |
| [Netflix TechBlog: Ready for changes with Hexagonal Architecture, 10/03/2020](https://netflixtechblog.com/ready-for-changes-with-hexagonal-architecture-b315ec967749) | El equipo Studio Workflows eligió principios hexagonales para una aplicación que integraba datos de varios sistemas y debía sustituir fuentes procedentes de un monolito. | Caso de una aplicación y equipo documentado en 2020; no describe toda Netflix ni demuestra su estado actual. |
| [Allegro: Hexagonal Architecture by example, 21/05/2020](https://blog.allegro.tech/2020/05/hexagonal-architecture-by-example.html) | Karol Kuc declara uso cotidiano y muestra un ejemplo práctico con dominio independiente, adaptadores REST y puertos de salida. | El proyecto de artículos es un ejemplo explicativo; el artículo no identifica toda la arquitectura productiva de Allegro. |
| [AWS Prescriptive Guidance: Hexagonal architecture pattern](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/hexagonal-architecture.html) | Definición, motivación y aplicación del patrón en integraciones AWS/Lambda. | Es guía del proveedor; no acredita que todos los servicios internos de AWS estén construidos así. |
| [Docker: Compose configs](https://docs.docker.com/reference/compose-file/configs/) | `configs.content` inserta configuración en el YAML y exige Compose 2.23.1 o posterior. | Una configuración no sustituye a un secreto. |
| [Docker: Compose Build Specification](https://docs.docker.com/reference/compose-file/build/#dockerfile_inline) | `build.dockerfile_inline` permite incorporar el Dockerfile en Compose; disponible desde 2.17.0. | El proyecto exige al menos 2.23.1 por el uso adicional de `configs.content`. |
| [Docker: Compose secrets](https://docs.docker.com/reference/compose-file/secrets/) | `secrets.environment` toma el secreto de una variable del host y lo concede a servicios explícitos. | Esta fuente está soportada en Compose; no equivale a un gestor de secretos empresarial ni funciona con `docker stack deploy`. |
| [Docker: instalación oficial en Ubuntu](https://docs.docker.com/engine/install/ubuntu/) | Repositorio APT oficial y paquetes Engine, Buildx y Compose plugin. | La guía está dirigida a una VM nueva Ubuntu 24.04; un host existente puede requerir resolver paquetes en conflicto. |
| [Docker: compose up](https://docs.docker.com/reference/cli/docker/compose/up/) | `--wait` y `--wait-timeout` esperan el estado running/healthy del proyecto. | Un healthcheck correcto no demuestra corrección funcional completa. |
| [Google Cloud: crear instancias](https://docs.cloud.google.com/sdk/gcloud/reference/compute/instances/create) | Flags de VM, disco, imagen, red y ausencia de service account. | Los comandos requieren proyecto, facturación, permisos y cuota. |
| [Google Cloud: imágenes de sistema](https://docs.cloud.google.com/compute/docs/images/os-details#ubuntu) | Proyecto `ubuntu-os-cloud` y familia `ubuntu-2404-lts-amd64`. | La familia selecciona una imagen mantenida; no fija su identificador inmutable. |
| [Google Cloud: máquinas de propósito general](https://docs.cloud.google.com/compute/docs/general-purpose-machines#e2_machine_types) | `e2-standard-2` tiene 2 vCPU y 8 GB de memoria. | Es una elección inicial para la demostración; no es un dimensionamiento de producción ni una estimación de precio. |
| [Google Cloud: redes](https://docs.cloud.google.com/sdk/gcloud/reference/compute/networks/create) y [firewall](https://docs.cloud.google.com/sdk/gcloud/reference/compute/firewall-rules/create) | Creación de VPC y regla SSH limitada a la IP indicada por el usuario. | Las políticas de organización pueden imponer restricciones adicionales. |
| [Google Cloud: SSH](https://docs.cloud.google.com/sdk/gcloud/reference/compute/ssh) y [SCP](https://docs.cloud.google.com/sdk/gcloud/reference/compute/scp) | Acceso SSH, transferencia y reenvío de puertos. | El puerto local debe estar libre; la sesión debe permanecer abierta. |
| [Git: git init](https://git-scm.com/docs/git-init), [GitHub CLI: autenticación](https://cli.github.com/manual/gh_auth_login) y [crear repositorio](https://cli.github.com/manual/gh_repo_create) | Rama inicial, login por navegador y publicación con `--source`, `--remote` y `--push`. | Los comandos de publicación se entregan para que el usuario los ejecute con su cuenta. |
| [Prometheus: instalación Docker](https://prometheus.io/docs/prometheus/latest/installation/) y [release 3.5.1](https://github.com/prometheus/prometheus/releases/tag/v3.5.1) | Imagen oficial, volumen TSDB y versión utilizada. | No se afirma que sea la versión más reciente. |
| [Grafana: Docker](https://grafana.com/docs/grafana/latest/setup-grafana/installation/docker/) y [provisioning](https://grafana.com/docs/grafana/latest/administration/provisioning/) | Imagen `grafana/grafana`, datasource y dashboard configurados como código. | No se depende de una instalación manual del dashboard. |
| [PostgreSQL 17.11](https://www.postgresql.org/docs/release/17.11/) | Versión PostgreSQL fijada; publicación 13/08/2026. | Los tags Docker no se presentan como digests inmutables. |
| [Kubernetes: startup, liveness y readiness](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/) | Diferencia entre arranque, vida del proceso y disponibilidad para recibir tráfico. | El esquema no valida la salud de un clúster que no se ha ejecutado. |
